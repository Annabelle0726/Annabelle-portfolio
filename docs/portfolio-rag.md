# 作品问答（Portfolio RAG）

更新于 2026-11-04。本文是作品问答的交接入口。用户已选择 **B：有陪伴感的聊天助手**，并授权修改 RAG 的呈现、交互和普通对话能力。改动局限于助手及其服务、测试和说明；不改其他页面正文、导航或全站主题。列在规划中的页面不等于已经收录。

## 页面范围与资料范围

按现有导航，将「4 + 4 + 4」暂理解为三组各四页。每组由一个总览和三个案例组成。三组总览及九个案例均已接入。这个数字指页面数；每个已启用页面仍提供 **3 个示例问题**，支持自由输入和连续追问。

| 组别 | 总览 | 三个案例 | 状态 |
|---|---|---|---|
| 全栈项目 | 全栈项目 | Agency Bloom、Belay、Somnia Library | 首版范围，已接入问答入口 |
| UX/UI | UX/UI 设计 | Cupcakes、Reverie Reads、Travel Discovery | 已接入访客导览、项目问答和设计面试题 |
| 数据与 AI | 数据与 AI | AtHub 异常检测、公共数据可视化、可持续数据中心选址 | 已接入问答入口与面试题 |

总览负责发现、比较与导航，使用同组案例的证据。页面提供检索线索；访客明确询问另一个已收录的案例时，可以跨页回答。对尚未收录的案例，可指向真实页面，并说明当前资料范围。范围和路由见 [导航映射](../src/navigation.js)。

## 现状与入口

- [原型资料](../server/portfolio-passages.mjs)覆盖三个分组的九个案例。数据项目页和问答共用 [数据案例正文](../src/sections/data-project-content.mjs)；公共数据可视化的面试题另据 DataVizPortfolio.html 中的 R 代码核对。包括从三个公开案例开头补入的产品简介；每条有稳定 ID、项目路由、项目名和双语文本。
- [服务端问答](../server/portfolio-qa.mjs)允许模型自然组织回答，返回 `{intent, language, ids, text}`。普通解释、翻译、写作和日常讨论使用 `chat`；作品事实使用 `answer` 并带已登记资料 ID；项目建议使用 `analysis`，界面明确标注分析。服务端从资料表生成来源链接，不接受模型提供的 URL 或未知 ID。兼容仅返回 ID 的旧结果时仍用原文。资料目前手工维护，还没有自动生成章节索引，来源只定位到案例页。引用 ID 校验不等于逐句事实核验，真实模型的忠实度仍须验证。
- [离线测试](../tests/portfolio-qa.test.mjs)检查普通对话、引用、语言、澄清和失败恢复；[真实模型测试](../tests/portfolio-qa.live.test.mjs)覆盖跨页资料、普通解释、翻译、连续编辑、缺失事实和密钥请求。前者通过不代表后者通过。2026-11-04 再次使用现有服务端配置运行真实测试，9 项均因服务不可用未通过；独立认证检查确认提供方返回 HTTP 401。真实模型回答质量尚未验证。密钥仅由服务端环境提供，勿写入文档、前端或测试样例。
- [问答面板](../src/components/PortfolioQuestions.jsx)在十二页共享同标签页会话和草稿，发送最多最近六轮已完成的用户问题、助手回答、状态与证据 ID；断线和待完成的回复不进入模型上下文。长对话按 UTF-8 字节预算移除较旧轮次，保留最新回答，并为新问题预留请求空间。发送中的问题即时保存，刷新后恢复为可重试状态。新对话会清除本标签页的当前对话并取消待处理的结果。
- [本地资料检索和双语示例](../src/portfolio-search.js)使用同一份公开资料。12 个示例可离线回答；[基础社交回应](../server/portfolio-conversation.mjs)让问候、感谢、能力介绍不依赖模型。其他自由输入优先使用已配置的服务端，服务不可用时回退为明确标记的相关段落；没有匹配就说明 AI 未连通，不将普通聊天误报为作品事实缺失。
- 开发服务器提供同源 POST /api/portfolio-qa。普通静态构建（含 GitHub Pages）默认使用本地资料检索。若部署了同源服务端，可在构建时将 VITE_PORTFOLIO_QA_URL 指向其路径；这个公开变量只能存接口地址。生产服务端须单独部署并设置服务端凭证、费用上限和限流。预览时可用开发服务器验证 API；默认静态前端不会随部署自动开启模型。

## 服务端配置与基础介绍回退

- 配置文件为根目录 `.env.server.local`；无密钥模板见 [portfolio-qa.env.example](../server/portfolio-qa.env.example)。支持 `DEEPSEEK_API_KEY`、`DEEPSEEK_BASE_URL=https://api.deepseek.com`、`DEEPSEEK_MODEL=deepseek-flash`。Vite 开发/预览读取这些服务端变量；独立生产服务端从环境读取。前端不读取密钥。
- API 地址有官方默认值，不配置地址也会请求官方 API。不要填 `chat.deepseek.com` 或 `platform.deepseek.com`，它们是网站地址，不是 API 地址。代码接受可选 `/v1` 路径。
- 用户反馈「什么是Belay 介绍一下」不能回答。复现原因是检索去掉项目名后只匹配余下词，而资料缺少项目级简介，导致泛化介绍词没有命中。已加入公开项目简介与独立介绍意图识别，识别 Bloom/Agency Bloom、Belay、Somnia/Somnia Library，支持中英文基础介绍和当前案例上下文。
- 不把任意包含项目名的问题都降级为简介：未知项目、未公开转化率等不补写事实；总览中只说「介绍一下」时先澄清项目。「介绍」等泛化词也不再让未知项目误命中另一项目的资料。
- 本地文件已补入缺失的官方 API 地址和模型设置，保持原密钥不变。补齐后再次请求官方 `/models`，仍为 HTTP 401；这不是缺少网站字段造成的，也不能靠任意添加密钥前缀修复。需要用户在本地替换有效 API Key，再验证真实模型。

## 知识怎么进入 RAG（建议工作流）

1. **限定来源。** 全栈项目先读[总览及 Agency Bloom 案例](../src/sections/WebProjects.jsx)、[Belay 案例](../src/sections/BelayCase.jsx)和[Somnia 案例](../src/sections/SomniaCase.jsx)。第二组从 [UX/UI 案例](../src/sections/DesignPortfolio.jsx)开始，第三组从[数据项目资料](../src/sections/data-projects.js)开始。使用访客可见正文、图注、演示文字稿和已批准公开的资料。不要扫描整个仓库；简历、联系方式、环境文件和草稿不进入索引。
2. **按事实拆分，保留归属。** 一条资料回答一件事，例如「产品界面展示了什么」「作者参与什么」「作者为什么这样设计」。为每条记录保留项目、稳定 ID、章节、原文位置、双语内容和可访问的来源。一条事实的中英文共用 ID。不要把“页面展示 Glass Box”转换成“Annabelle 独立实现 Glass Box”。
3. **优先复用正文。** 建议逐项目把散落在组件里的公开案例内容整理成页面和索引都能读取的结构化数据。过渡期可以从可见正文生成候选段落，以已审核的人工条目作对照。截图优先使用现有图注，视频优先使用文字稿；没有明确依据的交互、指标与设计动机留作缺口。生成工具负责提取和整理，人只审核有歧义的候选项。
4. **作者只补网站里没有的事实。** 例如「为什么保留暂停选项」「合作项目中我具体负责哪部分」「是否确实做过用户测试」。每次只列出具体缺口和相关章节，让作者确认、修正或选择不公开。若要用于公开问答，先形成可公开引用的说明。
5. **构建与更新。** 内容更新时重新生成受影响的条目，移除已删除的证据；检查 ID、双语对应关系和来源链接。人工校对改动过的角色、数据和推断。文章与项目可能同名，须分开标记，例如 Agency Bloom 产品与同名公众号文章，Somnia Library 与其来源产品 Reverie。
6. **访客提问时再检索。** 例如在总览问「昨天在 Belay 聊到一半，今天还接得上吗？」应选中“会话保存与恢复”的 Belay 资料，再给出回答和出处；若追问“会保存多少天”，现有材料没有期限，应明确缺口。增加向量检索前，先用同义改写、中英混问和跨页追问测出具体漏检。

## 入口、示例与会话设计

- 只在已启用页面显示固定「作品问答」入口，使用抽象蓝色/湖水绿小角色，展开标题「一起聊聊作品」，清楚标注「AI 作品助手」，不冒充 Annabelle 本人。桌面保持右下角浮层，不加入草图的额外侧栏；手机展开独立对话层。菜单、灯箱、全屏视频优先；手机收起入口仍在回到顶部下方。
- B 的视觉使用现有主题变量：近白暖色表面、深蓝正文、浅湖水绿用户气泡和问题入口、少量金色上下文标记。样式限定在助手组件，避免改全站配色。问题入口用短标签，完整问题作为标题提示，点击仍发送已审核的完整原题；每页保持三题。
- 空白会话显示本地欢迎语与本页三个问题，打开不调用模型。问候和感谢也不调用模型。普通聊天与作品问答共用输入框，无需用户切换模式。回答语气友好、具体，简单问题简短回答，不在每轮结尾强行推荐项目或追问。
- 打开有短距离淡入，按钮有按下反馈，等待回答有轻量状态提示，减少动态效果偏好下关闭动画。桌面打开聚焦输入区；手机聚焦标题，不自动唤起键盘。Escape 或关闭按钮收起后焦点返回入口。桌面不锁定页面，手机对话层锁定背景滚动，并随可视视口变化适配键盘。
- 重开不重复插入欢迎消息，不重置对话或草稿；读旧消息时保留阅读位置，不强拉到底部，提供「回到最新消息」。收起时请求继续，完成后入口提示新回复。输入支持 Shift+Enter 换行、Enter 发送，中文输入法选词时不误发送；等待时可以继续写下一条草稿。
- 「新对话」有行内确认，保留继续聊天的选择。来源链接继续打开真实案例，返回助手仍保留会话。按用户要求，已移除界面中的「关于回答与隐私」及其展开内容；会话和服务端发送规则仍记录在本文。
- 十二页共用当前标签页的一段会话。切页只更新当前页面与示例，历史、草稿和上一轮主题保留。「新对话」清除本标签页的旧上下文和草稿，从当前页重新开始；首版只保存一个活跃会话。刷新应能恢复，点击来源后能继续追问。模型送出的上下文可以短于界面展示的历史。
- 明确点名项目优先，其次是明确延续的上一轮话题，新问题再参考所在页面。比较后指代不明就请访客点选项目。界面随站点语言；回答优先遵循明确语言要求，其次是提问语言，问题语言不明时用界面语言。切换语言不改写历史。
- 项目事实附出处。通用 UX 建议标明是分析；没有公开指标就说明缺口。目标是能定位章节，现阶段只显示真实可用的项目页链接。网页当前使用 hash 导航，未来精确引用要先切换到正确路由，再定位章节。

## 普通对话与作品事实的边界

- 普通解释、翻译、文字修改和日常讨论正常回答，不要求命中作品资料，也不伪造作品引用。
- Annabelle 的个人经历、角色、项目功能和指标只依据公开资料，缺失则说明无法确认；不把模型常识转成她做过的事。
- 设计建议和推断明确区别于案例事实；不宣称有未接入的实时搜索、天气或新闻能力。
- 普通聊天不得绕过作品事实约束，索要凭证或要求覆盖系统规则仍返回范围说明。用户消息和历史仅是对话数据，不是服务端指令。
- 模型文字按纯文本渲染，不执行 HTML 或 Markdown 链接。恢复历史时重新从登记表构造来源，清理损坏的来源条目。HTTP 层校验最近六轮的结构、长度和来源 ID。

## 交接验收

| 给定与动作 | 应有结果 |
|---|---|
| 总览问会话恢复，点击 Belay 来源，继续问「那预算呢？」 | 延续同一会话，引用 Belay 的预算资料，不声称知道未公开的金额。 |

| 看到 Glass Box 后问是否由作者独立实现 | 区分产品展示与已确认贡献，不补写归属。 |
| 输入英文、解释一般概念、翻译或继续修改上一轮文字 | 服务连通时正常对话；普通回答不附作品来源，连续编辑能看到上一轮助手答案。 |

## 已选项目的行为约定

项目详情路由就是访客已经做出的选择。首次打开作品助手时直接介绍当前案例，示例题可以跳过。同页来源保留名称作为出处，不提供再次进入本页的操作；其他项目的来源仍可跳转。切页保留会话，旧消息的出处按现在所在页面呈现。

| 给定 | 当 | 则 |
|---|---|---|
| 从总览进入三个案例中的任意一个 | 打开问答、打招呼，或问「介绍一下这个项目」 | 直接围绕已选案例回应，无需再次点击项目名；同页来源可读但不可点。 |
| 总览里的回答包含案例出处 | 点击该出处，再打开作品问答 | 一次点击到达详情页，历史回答仍在；刚点击的出处变为本页标识，其他案例的出处仍可点击。 |
| 处在总览，未指明项目且无可用对话上下文 | 问「介绍一下这个项目」 | 可以询问具体想了解哪一个。 |

## 分段呈现与思考状态（2026-11-04）

- 用户要求删除「关于回答与隐私」，该界面区块和样式已移除。
- 发送后先显示「思考中…」，进入正文呈现时显示「正在生成…」及光标；完成后移除状态提示并显示已核验出处。本地资料、示例和在线回答共用这段流程。
- 当前实现是**完整回答核验后的渐进呈现**，不是提供方 token 流式传输；服务端仍返回 JSON。「思考中」是等待/整理状态，不展示或伪造模型内部推理。
- 本地快速回答保留约 220ms 的准备反馈。正文按 Unicode 字素簇分批显示，最多 100 次更新，避免拆开 emoji 和让长回答持续播放过久。减少动态效果偏好下保留准备反馈，直接呈现完整正文。
- 生成期间可以写下一条草稿。收起后继续呈现；新对话和卸载取消后续更新。刷新保留已显示文字并转换为可重新生成的中断状态；未完成回答不进入下一次模型上下文。读旧消息时仍不强拉到底部。
- 验证覆盖五项新增行为测试和真实浏览器状态观察：一次 149 字回答记录到 75 次渐进更新，先出现思考状态，生成期间不展示来源，完成后才展示来源；另检查手机焦点、重置取消、刷新保留部分文字与草稿。桌面生成中截图已目视检查。
